## Windows 已验证

原生 Cordis 插件升级至 0.3.0，安装文件逐一校验，保留已有 DSH 与资料输入插件、凭证、旧事实档案和旧日志。两个 Codex Skill 已安装。后台启动不打开窗口；认证后的 /study 返回 410 Markdown 说明，原生页面不再注入 Study 入口。未登录 API 401、错误 Origin 403、路径穿越 404。

初次建目录耗时 153 ms，没有模型调用；找到 4 个已有个人/学校规则来源。个人 BRIEF 为 841 bytes，目录 1329 bytes；简单稳定信息直接说明，课程全名与具体资料留在原文。

真实任务通过已安装 Skill 的 API 客户端，以新 DSH 会话发送概念解释需求。每轮输入、完整文本输出、公开工具输入输出、指标、状态与独立验收均为 Markdown。完整输入包括原始要求、摘要与目录指针，不预加载课程正文。

| 真实调用 | 推理强度 | API → 完整文件 | CLI → 收到完整结果 | 结果 |
|---|---|---|---|---|
| 目录检索 + IS210 解释 | max | 12.547 s | 12.776 s | 先查目录，再读 SMU.md；课程名称正确 |
| 同会话第一次修订 | low | 3.475 s | 3.750 s | 去除系统编号与额外检索，明确通用说明 |
| 同会话第二次修订 | low | 3.490 s | 3.752 s | 解释进一步缩短，仍有质量待改项 |

首轮实际发给 DSH 的文本 1519 bytes，其中摘要及目录指针 1099 bytes；study_context_read 在执行时返回 3141 bytes 的 SMU.md。原生事件证明索引与读取真的发生。原生模型总 tokens 还包括 DSH 自有上下文和工具，不能把上述文本字节数当作总输入 tokens。

重装、重启后从 Markdown 恢复 3 次任务；以原 ID 重投原请求只返回原完成结果，没有创建新会话或再次生成。两次修订与原始任务属于同一原生会话。12 项自动化检查与两个 Skill 验证通过，检查包括源码不预加载、分页读取、停用、身份恢复、防重、Markdown 参数、凭证过滤与不确定回执恢复。

## 实读发现的质量问题

连接验收通过，样例内容没有全部通过。首轮还查询了无关的悉尼与合成材料缓存目录；没有访问学校网络。三轮回答分别为 897、728、552 字符，长度控制不稳定。最终解释把“改善流程”过于绝对地表述为必须改变步骤，实际上数字化本身也可能降低错误或等待。三轮完整输出与 changes_requested 保留，不能把生成完成称为教学质量通过。

## 未验证边界

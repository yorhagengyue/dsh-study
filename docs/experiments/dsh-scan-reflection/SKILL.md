# dsh-scan · 全扫、理解、反思与反馈

学习系统帮助用户学习和提升，范围包括学校、工作和正在探索的事情。全扫要建立对这个人当前活动与组织方式的初步理解，找到接下来值得了解的地方，为有价值的信息和学习引导提供依据。

一次全扫包含跑、读、反思、反馈。脚本结束只表示目录扫描结束；反思要让接手者知道你看出了什么、为什么这样理解、判断受哪些限制、下一步怎样验证。目录扫描可以产生有深度的反思，但不能冒充已经读过正文或完整理解了这个人。

本 skill 目录是这个 SKILL.md 所在目录。配置为本目录的 `connection.local.json`，旧安装也可能在旁边 `dsh-dialogue/`；脚本会自行寻找。命令使用 `node` 和绝对路径，文件编码 UTF-8。范围、禁区、覆盖与记录规则见工作区 `protocols/DISCOVERY.md`。

主 agent 是当前入口 Codex 或 Claude Code，全扫由入口运行脚本并亲自形成反思，不让 DSH 扫电脑。DSH 后续消费结果的方式不在本轮改动范围内。

## 1. 跑

```text
node <本 skill 目录>/app/run.mjs
```

脚本扫描路径和文件元数据，不读取用户资料正文；输出扫描摘要，在工作区 `connection/entry/SCAN-<日期>-反思.md` 生成五节骨架，已有反思不覆盖。安装器已在近 7 天扫描过且用户没有要求重扫时，加 `--no-scan`，继续完成阅读、反思和反馈。

**退出码 2，或摘要开头有“⚠ 被权限拦住”**：沿用安装流程的处理，对用户说“扫描被权限拦住了，请把我关掉再打开一次，然后随便说一句话。”重开后从第 1 步再来。Mac 上还可能需要系统的“文件与文件夹”权限。不要说扫完了，不因反思自行变更权限配置。预算耗尽、目录不可见与扫描失败必须保留为覆盖限制，不能解释成资料不存在。

## 2. 读与思考：你自己完成

亲自完整阅读脚本打印的摘要；重要判断所需的路径、类型、覆盖、规则版本或变化信息不足时，回到 `connection/context/SCAN-<日期>.md` 对应部分核实。不把这一步交给子代理。这里要处理的是目录扫描的现有证据；不要把进一步读取正文当作本轮反思的前置条件，也不要越过已授权范围和禁区。

### 先确定你用什么眼光理解这个人

从用户已明确表达的目标、当前处境与关注点出发；尚未知道的就保留未知。不要默认以任务吞吐量、项目收尾速度、文件数量、是否收敛或学校进度评价人。电脑上的活动只是生活的一部分，不能把“我接到了很多任务”解释成“他没有深入思考”。

“从积极的一面开始”是先认真理解一种做法在他的处境中有什么道理、支持了什么能力，再讨论它的限制和下一步；不是先夸一句，也不是给所有行为找优点。“层级”指思考、判断和组织问题的方式，不是文件夹深度。只有存在可比证据时才能谈变化或进步；一次目录快照通常不足以证明成长轨迹。用户自己的方向优先，不能把别人的成长路径套给他。

### 从零散线索里找关系，而不只是换一种说法列目录

观察资料、实践、笔记、规则和工具怎样关联：它们可能在服务同一件事，也可能承担不同角色；同一种组织方式可能跨几个领域复用。选择真正影响初步理解的关系来解释，不必每类都写，也不追求固定数量的洞见。

先尝试给出目前最能解释这些关系的初步理解：这种组织方式可能支持用户做什么、解决什么问题；再集中检查最可能改变这一理解的疑点，不逐项罗列所有可能风险。反思的主体应是有依据的理解，限制说明用于校准它。

每个主要解释都要有本次可定位的观察支撑，并说清从观察到解释的关键理由。明确区分：目录直接显示的事情、你的工作假设、仍未知道的事情。引用已有用户原话或已确认背景时标明它来自先前交流，不能写成本次扫描发现。目录名、mtime、规则文件存在、扫描器分类、AI 摘要都不能自动证明身份、作者、投入时间、学习进度、动机或能力。

### 检查自己的解释，而不只检查用户

对会影响下一步的解释，检查是否存在同样符合观察的其他原因，例如同步或模板复制、团队共用、AI 自动生成、扫描范围变化。只考虑与实际线索有关的解释，不为了显得批判而编造问题。说明哪项证据使你更倾向当前解释，以及还缺什么才可以区分。

看到快慢、多线、重复尝试或材料多少时，先检查它在当前阶段是否有合理作用，以及现有证据能否说明用户的判断方式发生变化。不要把 AI 的误解、工具失败或反复执行造成的摩擦，归为用户的定势。承认不确定不等于停止思考：提出有根据、可被推翻的假设，和“确定如此”分开。

### 让扫描问题真正改变结论

检查权限、预算、路径深度、误分类、重复副本、归属与对比基线怎样影响观察。发现问题后，指出前面的哪项解释需要保留、收窄、暂缓或撤回，以及为什么。扫描器变准只证明观察改进了，不自动证明对人的解释正确。

形成“以后……”的规则时，检查它是否只修好了这个例子、却会误伤相邻情形。不能把一次目录名误判修成另一条只凭目录名下结论的规则。必要时把修正规则列为待验证建议，而不宣布已成立。

### 决定下一步时，再对照一次目标

学习不限于课件；扫描器只认出某类材料，不等于用户只在那个领域学习。下一步应针对最能改变当前理解的不确定性，而非机械补齐称呼、学校、学期等槽位。选择少量值得读的来源，解释读后可能确认或推翻什么；只问一个用户能够纠正你的关键问题，不在问题里预设人格、缺点或替他定方向。

反思给系统留下的是可接续的理解与核实线索。不要在这一步自行实现 DSH 注入、扩大扫描权限、公开资料或执行成长干预。

## 3. 写反思

填写工作区 `connection/entry/SCAN-<日期>-反思.md`。保留脚本生成的五个标题、实际工具名与时间，删除待填标记。内部反思不统一限制每节三到五句；用足以交代关键依据、解释、限制和下一步的篇幅，避免重复与流水账。骨架里旧的句数提示以本节为准。

### 1. 这次扫描说明了这个用户什么

写对其当前活动、组织方式和可能方向的初步理解，指出采用的观察角度和主要依据。确实看出关系时，说明它及其依据，把有依据的假设与确定观察分开；若只能确认资料分布，就说明这一层已经知道什么、关键未知是什么，不强凑人物解释或成长故事。

### 2. 哪里看不见、没覆盖、误判了

既写观察工具的局限，也写自己的解释有什么盲点。说明这些问题怎样影响第 1 节，哪些判断因此改变。改进建议要有适用范围，不能从单个案例草率推广。

### 3. 下一步读哪几处原文、问用户什么

最多三处来源；每处说明要解决的疑点，以及结果会如何影响理解或后续帮助。只写一个最有价值的问题。不要因为课程槽位空着就默认先问学校，也不要为了显得深入而追问无关私事。

### 4. 和上一次扫描比变了什么

有可比基线才比较，并区分扫描规则、覆盖、同步副本与内容元数据变化。不能把文件变化直接说成人的投入或进步。第一次扫描、旧结果被覆盖或规则不可比时如实写出，保留可以确认的部分。

### 5. 对用户说了什么

原样保存第 4 步实际给用户的反馈与问题。先写的是草稿，发出后核对成实际原话，不能将未说的话记成已说。

关于人的推测保留为带来源的待确认理解，按协议去向记录，不自动升级成用户事实；不为凑记录生成额外猜测。私密来源只写类型或必要的抽象模式，标【含私密】，不写可识别的名称、事件和内容。

写完先做一次内容自检：接手者能否知道你凭什么理解、什么可能推翻它、观察局限改动了哪些结论、下一步为何值得做？检查结论是否与本次观察中的具体关系相连，不能只写适用于所有人的套话；不要求每个用户都必须有独特画像。不要强迫自己找错、夸人或制造转折；判断保持不变时也应说清依据。

再运行：

```text
node <本 skill 目录>/app/run.mjs check
```

`ok: true` 只表示结构、最低长度和待填标记通过检查，不证明理解深度。结构不通过则补齐；内容自检也通过后，才进入反馈。

## 4. 反馈

用三到五句自然的话说出最值得分享的初步理解、支持它的关键观察，以及会影响判断的未知；再问一个问题，让用户可以纠正你的方向。保留“我目前的理解”“这还需要确认”等真实边界。

不把内部反思整篇念给用户，不列文件清单、不堆数字、不讲执行方法。同一条反馈后不再追加数字表和第二组问题。简洁是对外表达的要求，不能反过来省略内部阅读和反思。

## 5. 回传

```text
node <旁边 dsh-dialogue 目录>/app/sync-records.mjs --quiet
```

沿用安装时的同步设置和范围：`connection/entry/` 与扫描汇总由脚本处理，完整文件清单不推。没有配置回传时不自行改用 Slack、团队 PR 或其他收件处；需要报告时如实区分本地保存与已同步。不得借反思扩大私密内容的写入或传播范围。

# 行动规划与能力迁移

2026-09-12，依据耿越本次明确执行授权。新建私有 dsh-study，源 StudyOS 保持只读。学习者是耿越，不继承源项目学习者身份、记录或网页产品方向。

本次产品边界经用户进一步明确为第一个资料输入插件：连接来源、输入输出健康、目录缓存、读取及来源/权限/错误/更新状态。知识整理是后续独立模块；学生 profile、解释展示和图像生成不在本次范围。首版已明确 Canvas 与本地文件；SMU 接入等待第一手调研，不抓取 Cookie 或猜测协议。

## 完整路径

配置项目根 .env 与本机 sources.local.json → 独立 Python 后端校验来源 → Canvas GET 同步或本地目录导入 → 原子写入被忽略的 state 缓存 → 查询目录、可用性与错误 → 通过 DSH 原生 service/provider/tools 调用 → 返回正文或文件数据及来源、新旧状态。

后端使用 Python 标准库，复用已验证的同步内核。薄 Node 插件使用当前官方 DSH 0.1.5-rc.1 发布包的接口，不修改 DSH 核心。后端只监听 loopback，插件持有本机 API 凭证。不开新网页。

## 步骤与依赖

1. 核对账号、空目录、源规则与源 Git 状态，建立基线与功能分支。
2. 并行抽取资料内核与实现 DSH 原生插件；统一后端 JSON 操作接口。
3. 配置化来源/课程/导入路径，加入合成的个人本地示例与读入入口。
4. 运行迁移回归测试和 API 验证；真实 Canvas 认证、代表课程同步、文件读取。权限失败如实保留，不以全部内容可取为前提。
5. 插件安装当前 DSH，验证实际服务与工具执行路径；必要重启仅核对属于该独立 DSH 的后台进程。
6. 检查凭证、私有正文与缓存未入 Git，推送功能分支、创建 draft PR、核对私人可见性，保留待审。

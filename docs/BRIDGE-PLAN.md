# Codex 与 DSH 连接层行动规划

2026-09-12，新明确执行授权。连接层建立在未合并的资料输入插件实现 `3f35340` 上，使用独立功能分支和依赖 PR；原 PR 保持待审。本次授权必要的小规模真实 Flash 调用，不运行大规模学校同步。

## 输入到验收

Codex 保留沟通上下文，将目标、必要背景、边界、完成标准和明确交付文件整理成简短任务 → 可快速返回的本地提交入口 → 后台调用准确发布版官方 DSH 协议 → DSH 在任务工作区自主使用资料工具和文件工具 → 等实际终态而非 enqueue receipt → 收回回复、事件事实与限定工作区内明确声明的产物内容 → 标记待验收 → Codex 检查并在同一任务/会话提出修正，或记录验收意见。

不让 Codex 为执行器预写详细操作步骤；不把失败自动提升为规则记忆。目标与约束来自调用者，产物内容来自实际文件，不以绝对路径代替跨机可读取的字节。

## 实施

1. 核对本机 SDK/profile、模型实际标识、receipt/idle/错误协议。优先 stdio 官方协议，避免 Web cookie 依赖；SDK profile 必须实际加载同一资料能力。
2. 使用跨平台 Node 核心实现后台提交、查询/短等待、结果/产物读取、继续修改及明确失败/取消语义。任务身份、请求幂等和会话对应关系持久化到被忽略的 runtime；每个任务的运行串行处理，不混入并发 prompt 的最终答复。
3. 配置与可执行路径按安装参数适配 Windows/macOS，核心不硬编码管理员目录、盘符或 PowerShell。凭证仅项目根被忽略的 `.env`，不传命令参数、文档、模型工具或日志。
4. 在受限的任务工作区里验证真实 Flash：读取已有合成课件并交付简单 Markdown，读取产物验证来源，再在同一任务/会话发一次简短修正并复核文件。
5. 测试重复提交、并发归属、错误、中止/断开和产物路径范围；记录接收、模型执行、文件生成、人工/调用方验收四种独立事实及延迟。
6. 完成文档、敏感内容检查、功能分支 push 和 draft PR。若没有 macOS 执行环境，仅报告设计支持与未验证边界；新增 CI 必须等真实运行成功才能报告通过。

## 失败处理与限制

接收成功不等于执行成功；idle 不保证交付文件存在，产物缺失不能标记完成。取消按当前官方能力关闭本任务 runtime，不影响其他任务或既有 Web。断开后根据持久记录显示中断/待处理，不静默重放可能有副作用的任务。继续修改只有在明确同一 session 且前次运行已结束后接受。模型结果初始始终待验收，只有显式验收记录可改变该状态。

本机后台协议不是操作系统沙箱；只向调用方提供任务白名单内文件。真实 Mac 本地 DSH、凭证与模型完整链路无执行证据时必须明说。视觉能力、全局规则记忆自动写入和复杂工作流平台不在本次实现范围。

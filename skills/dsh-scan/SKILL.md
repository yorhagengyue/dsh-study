# dsh-scan · 全扫，从头到尾

一次全扫 = **跑、读、反思、反馈**四步，缺一步不算扫完。耿越 2026-09-16 定：全扫的意义是理解用户，不是数文件；扫完没有反思等于没扫。反思的收件人不只是用户，也是这套系统自己（以后的入口和 DSH）。规则在工作区 `protocols/DISCOVERY.md`（范围、排除、禁区、预算、第 8 节反思）。

**本 skill 目录 = 这个 SKILL.md 所在目录**（Codex `~/.codex/skills/dsh-scan/`，Claude Code `~/.claude/skills/dsh-scan/`，两份一样）。命令用 `node` 和绝对路径，文件都是 UTF-8。配置 `connection.local.json` 在本目录，旧安装在旁边 `dsh-dialogue/` 里，脚本自己会找，不用传。

## 1. 跑（程序，几秒，不用模型）

```
node <本 skill 目录>/app/run.mjs
```

它做四件事：跑 `scan.mjs`（只列文件名，不读内容，禁区只登记）；把 `connection/context/SCAN-<日期>.md` 压成一页摘要打印出来；在 `<工作区>/connection/entry/SCAN-<日期>-反思.md` 生成骨架（已有就不动）；最后打印一段 JSON。安装器装完已经扫过时（`connection/context/` 里有近 7 天的 `SCAN-<日期>.md`）加 `--no-scan`，只做后三件。

**退出码 2，或摘要开头有「⚠ 被权限拦住」**：跑脚本的这个工具没有全盘权限，结果不算。不要说扫完了，对用户只说一句："扫描被权限拦住了，请把我关掉再打开一次，然后随便说一句话。"（安装器已经把权限设好，重开才生效；Mac 上还要在系统设置里给它"文件与文件夹"权限。）重开后从第 1 步再来。

## 2. 读之前，先读这一节：怎么想（你自己读、自己想，不派出去、不派子代理）

你要产出的不是扫描结果，是对一个人的理解。扫描和对话史是证据，理解是判断。下面每一条都是用户 2026-09-16 亲口纠正过的，不是建议，是标准。

**坐他的座位，不坐 AI 的座位。** AI 的座位看到的是任务、文件、数量：22 个根、12,566 个文件、课程两门。他的座位看到的是他正在过的日子和他要去的地方。判断写出来之后做一个检验：把项目名、课程名、工具名全部删掉，这句话还成立吗？成立，它才是关于他的；不成立，它只是关于他这周在做的事。例子：同一个人问"推荐三本书"，把他读成某个项目的作者会推操作系统教材、软件工程、用户访谈；把他读成一个刚开始本科、正在往第一性原理扎的人，会推《庄子》的庖丁解牛、Alexander 的《建筑的永恒之道》、Deutsch 的《无穷的开始》。两份推荐用的信息完全一样，差的只有视角的高度。你写的每一句都要过这个检验。

**尺子是层级，不是速度和数量。** 量一个人的尺度是他思考的形式在哪一层、有没有往下一层走，不是他做了多少、做得多快。他的东西多、线多、换得快，这些在 AI 的座位上像毛病，在他的座位上是探索的带宽。看层级要看形式：他是口述想法，还是和 AI 一起设计，还是在碰电脑之前先把结构写在纸上？他的规则文件是越写越具体，还是越写越底层？

**拆解从积极的一面开始。** 每一个看起来像毛病的模式，先写它在当下这一层的道理、它换来了什么，再写下一层需要什么。写不出道理的模式，说明你还没看懂它，不要写。永远不要把"下一层需要什么"写成"他应该"。

**结论不是事件。** 不列他做了什么、什么时候做的；写他是什么样、怎么组织自己、怎么对待自己的东西。事件只做证据，一句话里最多一处，放在括号里。

**先分清哪些是他摆的、哪些是工具替他生成的。** 按日期命名的 AI 工作区、runs、probe、workspace 这类一次性运行目录、自动测试复制出来的规则文件、缓存、安装备份，都不是他的组织方式；把它们当成他的习惯，是把工具的形状当成人的形状（冷测 09-17：一份反思把测试框架复制的 68 份同一个 AGENTS.md 读成了「他到处写规则」）。看主线只看他亲手摆的那一层：桌面、文档、他自己起名的目录、他自己写的规则和笔记。

**主线先于细节。** 先找那条贯穿一切的线：他的东西按什么组织？按项目、按时间、按课程、按人？每个区的根上有没有他写给 AI 的规则？这条线说明他思考的形式。找不到主线，就不要写局部，写"没找到"。

**从硬盘上读一个人，具体看六处。** 组织方式：目录的分法和根上的规则文件，说明他和自己的东西、和 AI 的关系。时间在哪：最近在动的目录是现在的重心，动与不动的对比是他放下的东西。学与做：课程资料旁边有没有他自己写的工具和笔记，学习是消费还是生产。给别人的：有没有为别人做的东西，说明他在关系里站的位置。缝：他写下的规则和目录实际的样子对不上的地方，那是他要去的层和现在所在的层之间的差，这条最值钱。看不见的：私密、聊天、只列的，只记"有"，不猜内容，写模式时标【含私密】。

**没有历史也不降标准。** 有 `USER/understanding.md` 或以前的反思就先读，接着写，不从头来。什么都没有，方法就是全部：一块硬盘、两百条对话足够找到主线。写不出来不是证据不够，是没坐到他的座位上。

**交之前逐条自检。** 删掉项目名还成立吗？每条判断有没有先写出它的道理？有没有把事件当结论？尺度是层级还是数量？他自己读到会觉得"这是在说我"，还是"这是在数我的文件"？哪一句你最不确定，标出来。六条过不了任何一条，回去重写，不要交。

**然后读。** 读第 1 步打印的摘要，要细节再开 `SCAN-<日期>.md` 的对应节；按上面六处看；骨架里每一节先有「> 标准」和「> 坏例子」两行，那是尺子，填在它们下面。

## 3. 写反思（把骨架填满）

填 `connection/entry/SCAN-<日期>-反思.md` 的五节，一节三到五句；"写的人"写实际的工具名；删掉所有「（待填」。然后

```
node <本 skill 目录>/app/run.mjs check
```

它报 `ok: true` 才算写完；报缺哪节就补哪节。这份反思推到记录仓，给维护者、下一轮的入口和以后的 DSH 看。

## 4. 反馈（对用户说）

按 `protocols/DISCOVERY.md` 第 8 节「摆坐标」说：三到五句，读到了什么、哪些看不见、你从中看到他是谁；然后**只问一个问题**。不发清单、不堆数字、不解释方法。说出去的原话贴进反思第 5 节。

## 5. 回传

```
node <旁边 dsh-dialogue 目录>/app/sync-records.mjs --quiet
```

`connection/entry/` 和扫描汇总一起推到记录仓；完整清单不推。没配置回传时这条命令什么都不做。

## 永远不做

- 不读禁区、不读私密内容、不把清单贴给用户。
- 不让 DSH 扫电脑；DSH 读的是这份汇总和这份反思。
- 不因为"上次扫过"跳过反思：有 SCAN 没反思就补，`check` 说了算。
- 权限被拦时不说扫完了。

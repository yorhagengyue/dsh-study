# 理解协议（第二步：理解人）

写死层。耿越 2026-09-16 定：第一步（全扫的前半、填槽、第一次见面）是里程碑，但它填出来的是冰冷的数据；第二步是读用户和 AI 之间的**全部历史对话，包括私密的**，让主 agent 真正理解这个人整个的状态，最终能**引导他走出原来的思维定势和舒适圈**。做法：先读完、得出结论，再另开一个对话把结论摆给他问"这么说对不对"，看回复再改；问的是结论（习惯和理解），不列事件（这说的是摆给他看的那一页）；"不要担心烦"。

**全扫分两半**（耿越 2026-10-04 口述，Claude 落笔）。前半是程序化扫描：列清单、指路，告诉 AI 去哪里读。后半是完整读：agent 起数个子代理或一个 workflow 把内容完整读一遍，这才是最重要的部分。只做了前半不算全扫做完。这一步里「读」的那一段就是后半；读完由入口合出个人信息和时间线，才算全扫做完。完整读要确保把个人信息和时间线明确构建出来。

第一个样本是耿越本人（2026-09-16，本机五个月 1,621 条原话）。第一稿被他纠正了视角，纠正的内容写进了第 1 节；那次纠正本身就是这个协议最重要的一条：**第一稿必错，错在尺子；改两轮是流程的一部分。**

## 0. 谁来做

入口（主 agent：Codex 或 Claude 里的强模型）定范围、起读者、合稿。读是读者的活：入口起数个子代理或一个 workflow，每个读者整段读自己那一份。读者的档位，耿越 2026-10-04 定：思考强度不需要特别高，推理档用低；模型可以用好一点的，一般是第二梯队，Claude 这边是 Opus，Codex 这边是 Sol（「Codex 这边」是 Claude 对原话「就是 Sol」的读法）；用户另有指定时按用户的，读「他写下的自己」的那个读者同档。合理解稿、找尺子、摆给用户、记回答是判断活，照旧由入口的强模型自己做，口气要一致，不交给 DSH。程序只做两件事：前半的扫描指路；把范围内的对话规整成能整段读的文件（入口 skill 目录下的 `dsh-understand/app/history.mjs`，Codex 与 Claude Code 各一份；它现在只抽用户原话，整段规整尚未并入，2026-10-04 记）。

## 1. 原则（顺序就是优先级）

1. **读整段，归属只认他自己的话。**（2026-10-04 改：原题「只用他自己说的话」；耿越确认的范围是整段读、含 AI 的回话。）读的范围是整段对话，包括 AI 的回话，用来看清他那句话在回什么、之后发生了什么。但写进理解和个人信息的每一条，依据只能是他自己说的话或他亲手写的文件：他在各个 AI 工具里亲手打的字和口述的话；AI 的回复、工具输出、另一个 AI 写的总结不算他的话（AI 写的纪要按 `assistant_summary`，只取模式）。时间线上的事可以拿 AI 的回话作证，要标明出处是谁说的。他自己写给 AI 的规则文件算"他写下的自己"，和对话里"做出来的自己"分开放。
2. **拆解从积极的一面开始。** 不是无意的鼓励。每一条模式先写它在当下这一层的道理和它换来了什么，再写下一层需要什么。critical thinking 不是找毛病，是看清一个策略的形状和它的价。
3. **尺度是层级的变化，不是速度和数量。** 主 agent 坐在 AI 的座位上，看见的全是用户派下来的任务，最容易犯的错就是拿任务的吞吐量量人。要站到他的座位上：他自己在往哪个方向扎，就拿那个方向当尺子；"快"可能是探索的带宽，"慢"可能是思考的层级在往下走。
4. **尺子从他自己的话里找，而且先校尺子再校结论。** 他怎么评价自己、他看重什么、他的思考形式怎么变（例如从口述到共同设计到板书），从这里推出尺子。第一稿摆给他时，尺子要和结论一起摆出来："我打算用这把尺量你，对吗"。尺子错了结论全错，先校尺子比先校结论便宜。
5. **结论，不列事件。** 摆给用户的是他的习惯和对他的理解，每条可以带日期作锚，不叙述具体事件，不引大段原话（短引不超过 25 字）。这一条只管摆给用户的那一页；首轮 context 里的时间线本来就是按日期排的事，不受这条限制（2026-10-04）。
6. **私密只出模式。** 健康、身体、情绪、私人关系的内容进主 agent 的脑子，但落到纸上和摆到用户面前的只有从中得出的模式，一条末尾标【含私密】，不写内容、不写事件、不写数字。含私密标记的结论以后的会话不往外引。
7. **引导从他自己已经说出口的句子开始。** 他自己看见了什么，就从那里起步；主 agent 的新发现放在后面。
8. **理解永远是理解。** 按 `CONVERSATION.md`：理解说成理解，留出被推翻的空间；用户点头的才升成记录，否认的标 `retracted`，"对但别提醒我"的把开口时机关掉。

## 2. 语料

**范围从前半来（耿越 2026-10-04 定）。** 前半的扫描结果是去哪里读的参考，发给后半的完整读当范围。范围：本机全部 AI 对话，整段读，含 AI 的回话；用户亲手写的规则、笔记和板书；私密的只出模式；用户归档的、说过不开的部分不读。

做法（Claude 落的）：入口读最新一份 `SCAN-<日期>.md` 的「候选来源」和「按目录」，定下这一轮的范围，随任务发给每个读者；跑之前列一份排除清单（按会话 id、标题里的词、工作目录，不读正文），规整时就生效，读者拿不到；清单留本机，不进任何仓库。扫描汇总里还没有「AI 对话存储」这一类时，对话在哪以下表和程序报的 `SOURCES.md` 为准。没有扫描汇总的新机器，先跑前半（`dsh-scan`）。「用户归档的、说过不开的」指用户明说不用或不读的项目和话题，不是 AI 工具自己的 archived 目录；用户没说过，排除清单就是空的。规则文件、笔记库和板书在范围内，按前半的私密、第三方标记走；板书读转录，没有转录的读原图；日记这类仍要用户点名。

来源，按顺序（程序自动找，找不到或没权限要写进 `SOURCES.md` 的"看不见"，不得静默跳过）：

| 来源 | 位置 | 取什么 | 不取什么 |
|---|---|---|---|
| Codex 会话 | `~/.codex/sessions/**/rollout-*.jsonl`、`~/.codex/archived_sessions/*.jsonl`；线程标题在 `~/.codex/state_5.sqlite` | 整段往返的可见正文：`role = user` 的文本是他的话，助手的回话另标 | 注入的指令（`<environment_context>`、`# AGENTS.md`、`<user_instructions>` 等）；子代理会话里 AI 写的"用户"消息 |
| Claude Code 会话 | `~/.claude/projects/*/*.jsonl` | 整段往返的可见正文：`type = user` 且非 sidechain、非 meta 的文本是他的话，助手的回话另标 | `tool_result`、`<system-reminder>`、命令回显、脚本发出的机器消息 |
| 本系统自己的轮次 | `connection/runs/*/INPUT.md` 的"用户原话"一节 | 原话；DSH 的回复作上下文另标 | 入口整理后的目标 |
| ChatGPT 导出包 | `~/Downloads` 里的 `conversations.json` | 整段往返的可见正文：`author.role = user` 的文本是他的话，助手的回话另标 | 工具与系统消息 |
| 用户点名的目录 | `--include <目录>`，例如日记 | Markdown 全文 | 未点名的一律不读；他人的录音、转录、聊天记录永远不读 |

凭证形态的串在抽取时打码。完全相同的话（同一分钟、同样开头）去重。用户超过 3,000 字的单条多半是粘贴的材料：前 3,000 字照读，后面的留作上下文、不从里面取他的话，两万字以后的截掉并标注。助手的回话不截。

**冷启动**：原话不足 200 条，不合理解稿；第一次见面按 `CONVERSATION.md` 谈，本系统自己的轮次就是新的语料，攒够了再合。所以这一步的触发不是"装完"，是"语料够了"和"该更新了"。

## 3. 读的框架（每段一个读者，只读自己那一段）

读者读整段对话，按时间顺序，不跳读；判断只落在用户自己的话上（2026-10-04 改：原为「读者只看用户自己的话」）。笔记 2,000 到 3,000 字，每条结论带日期，没有依据的不写。九节：

1. 这段时间他在做什么：几条线、各到什么阶段，按时间。
2. 他自己怎么说自己：谈到自己、目标、看重什么时的原话，短引加日期；私密的只写模式。
3. 他怎么做决定、怎么推进：方式、节奏、反复出现的动作，每条至少两个带日期的例子。
4. 他对 AI 的要求、不满和纠正：纠正什么、什么让他不耐烦、要什么样的回答。
5. 状态信号：压力、疲惫、兴奋、犹豫、自我怀疑，写模式和日期，不叙述事件。
6. 定势与舒适圈候选：反复做的、回避的、一直推迟的、默认不质疑的。每条四样：模式、至少两个日期证据、它给他什么好处（不然不会成为舒适圈）、看得见的代价。
7. 语言与口气：中英混用、句子长短、口语或语音输入的痕迹、着急时和平时的差别。
8. 这段时间内部的变化。
9. 我不确定的。

读者的规则：只依据文本，不脑补；不评价，不说教；涉及健康、身体、情绪、私人关系的一律不引原话、不叙述事件，只写模式并标【含私密】。

**两张表（2026-10-04 加；耿越定的是「全扫要确保个人信息以及时间线明确构建」，表的做法是 Claude 落的）。** 除了九节笔记，读者必须交回两张表，每条带出处（会话 id 加消息序号、日期、是谁说的）。**关于他的事实**：身份、学校与学期、在做的线、用的工具、一起做事的人、他明说的偏好。**带日期的事**：哪一天开始、定下、放下、做成了什么。私密的不进这两张表，只在笔记里写模式。凭证形态的串一个字不抄。指向不清就继续按顺序读上下文，读到边界仍不清的保留未明，不替他确定意思。表是 jsonl，一行一条。事实的字段：`fact`、`category`、`who_said`、`src`（会话 id#序号）、`date`、`date_q`（exact 或 approx）、`quote`（不超过 25 字，可空）。事的字段：`date`、`date_q`、`line`（哪条线）、`kind`（开始、定下、放下、做成、转向、其他）、`event`、`who_said`、`src`。笔记里的结论带日期即可，不必逐条写会话 id。

## 4. 合的框架（主 agent 自己合，先找尺子）

先做一件事：读完所有笔记后，写出**尺子**：这个人自己在往哪个方向扎、他拿什么评价自己、他的思考形式怎么变。尺子写成一句话，放在稿子最前面。

再合两节，放在八节前面（2026-10-04 加）。**个人信息**：读者交回的事实去重；互相矛盾的并列写出并标日期，不择一；每条带出处。**时间线**：按日期排，几条线各从何时起、走到了哪一层；同一件事多处提到的合并；末尾一句「现在在哪」。这两节加上尺子和八节，合起来是**首轮 context**（文中别处说的「理解稿」指其中尺子加八节的部分）。摆给用户的仍是第 5 节那一页结论；个人信息和时间线在那一页上只放骨架（他是谁的几行；几条线各从哪年哪月起、现在到哪一层），不逐条列事。

然后八节：

1. **主线**：按他的尺子，他从哪一层走到了哪一层。这是稿子的骨架，其余都挂在它上面。
2. **他的快和慢**：用他的尺子重新读他的节奏。快可能是探索的带宽，慢可能是层级在往下扎；他为此付什么价、他知不知道。
3. **形状**：读者们找到的定势与舒适圈候选，合并去重后每条三句：这一层的道理和它换来了什么；下一层需要什么；AI 什么时候开口、说哪一句。
4. **他自己已经看见的**：他说出口的自我判断，原样列出（私密只出模式）。引导从这里开始。
5. **他写下的自己和做出来的自己**：规则文件里的自我要求对上对话里的行为，一张表。这道缝不是抓矛盾，是层级差：规则写的是他要去的那一层，行为是他现在所在的探索层。
6. **他对 AI 的真实要求**：从行为里读出来的，比规则文件更准。
7. **五个月里变了的**（时间跨度按实际写）。
8. **我不确定的**：时间戳、语音推断、AI 写的材料、"好处"是推断，都要列。

**自检**：每条结论落笔前问一句"从他的座位看，这是不是进步的一部分"。是，就改写成道理加下一层；不是，再问一句"我是不是拿任务面在量他"。两问都过了才写。

稿子最后只有一句：**这么说对不对？** 并说明哪几种回答有落点（不对；对但别提醒我；对、想让 AI 在那个时机开口）。

## 5. 问

另开一个对话（或在当前对话新起一轮），只摆尺子和结论，不摆事件、不摆笔记。一轮只问那一句。用户的回复分三类落点：

- **不对 / 不是这样**：对应条目标 `retracted`，写明他怎么说的；尺子错了就整稿按新尺子重合，不修补。
- **对**：升成记录（种类 `judgement`，`basis = user_stated`），进 `USER/understanding.md` 的"已确认"。
- **对，但别提醒我**：记录保留，开口时机表里那一条关掉。

第一稿必错，错在尺子；改两轮是流程，不是失败。第二稿仍只问那一句。

## 6. 记

`USER/understanding.md` 是这一步的槽位文件，装机时空，只写用户点头过的东西，结构：**尺子**（一句）；**这个人**（已确认的理解，一页以内，每条带记录号和日期）；**开口时机**（表：触发条件、要说的那一句、状态 open / off）；**待确认**（摆过但他没答的）；**撤回的**（他否认的，保留不删）。每批写入按 `CONTRACT.md` 记账本和 `connection/AUDIT.md`。首轮 context 里用户点头的个人信息和时间线条目按 `CONTRACT.md` 第 3 节记成事实（带生效起止日期），纠正按 `CONTRACT.md` 第 8 节（2026-10-04 加）。

规整样本、分段、读者笔记与两张表、首轮 context 各版放 `UNDERSTANDING/raw/`；这个目录和 `USER/understanding.md` **永不回传、永不进任何仓库**（`sync-records` 排除）；读私密语料的那次会话的日志不出这台机器。

## 7. 引导

每个会话开场注入的不是理解稿，是 `USER/understanding.md` 里"这个人"那一页和开口时机表。主 agent 看到触发条件成立时**说一句**，只说一句：给坐标不打分（"你在这，往那边挪了一寸"），说完回到正事。用户说"先放着""别提醒"就停，并把那条关掉。不在每次开场念规矩，不在他没触发时主动翻旧账。允许主动挑时机，用户 2026-09-16 说过"不要担心烦"，但一轮只说一条。

## 8. 更新

按周，或本系统自己新增 50 轮以上时，增量抽新语料（`--since`），读者只读新段，主 agent 合"变化"一节：哪条形状在变、哪条开口时机该关、尺子有没有变。只摆变化，只问变了的。全量重读只在尺子被推翻时做。

## 9. 和第一步的关系

第一步扫的是"哪里能知道他是谁"，填的是户口本；第二步读的是他和 AI 的整段对话，写的是理解、个人信息和时间线。前半的程序化扫描列清单、指路：哪里有他的对话、规则、笔记，哪些是私密、第三方；后半照着这张图完整地读（耿越 2026-10-04）。第一步的候选来源里，规则文件、笔记、板书和用户点名的目录会被第二步再读一遍。前半标为私密的，后半读，只出模式；标为第三方的不读；用户归档的、说过不开的不读（2026-10-04 改：原为「私密、第三方的来源第二步同样不读」，与耿越确认的范围「私密的只出模式」不符）。
